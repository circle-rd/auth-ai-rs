Everything below is exported from the crate root, `auth_ai`. All I/O methods are `async fn`; the few synchronous ones are marked. Fallible functions return `Result<T, AuthAiError>` (the crate also exports the alias `auth_ai::Result<T>`) and document their error codes under `# Errors`. Secrets and tokens are `SecretString`s: they never print in `Debug` and are zeroed on drop.

## `AuthClient`

The OIDC relying party for auth-service: authorization code with PKCE, refresh with RFC 8707 resource narrowing, logout, revocation and introspection. It keeps no session: you persist the handshake, the tokens and the claims where it suits you. It is cheap to clone. Options are in [Configuration](/docs/reference/configuration).

| Member | Description |
| --- | --- |
| `new(config: AuthClientConfig) -> Result<AuthClient>` | Builds the client on the default `reqwest` transport. `CFG_001` when the HTTP client cannot be built. |
| `with_transport(config, transport: Arc<dyn Transport>) -> AuthClient` | Synchronous, infallible. Builds the client on your own [transport](/docs/reference/configuration#transport). |
| `config(&self) -> &AuthClientConfig` | Synchronous. The validated configuration. |
| `transport(&self) -> Arc<dyn Transport>` | Synchronous. The transport every request goes through. |
| `start_login(prompt: Option<Prompt>, login_hint: Option<&str>) -> Result<LoginRequest>` | Generates `state`, `nonce` and the PKCE verifier and returns the authorization `url` and the `handshake` to persist until the callback. `OIDC_001` when discovery fails. |
| `handle_callback(callback_url: &str, handshake: &LoginHandshake) -> Result<LoginResult>` | Validates the authorization response (a repeated parameter, `error`, `iss`, `state` and `code`), exchanges the code, verifies the ID token and enriches the claims from UserInfo. Failures are `OIDC_002`, `OIDC_003` or `TOK_001`. |
| `verify_id_token(id_token: &str) -> Result<IdTokenClaims>` | Verifies an ID token of the provider, with no nonce check. `TOK_001`. |
| `fetch_userinfo(access_token: &str) -> Result<UserInfoClaims>` | Reads UserInfo. `OIDC_004` without a `userinfo_endpoint`, `OIDC_003` when the request fails (the endpoint must be HTTPS). |
| `apply_userinfo(claims: IdTokenClaims, access_token: &str) -> Result<IdTokenClaims>` | Fills the profile and entitlement claims the ID token omits from UserInfo, never replacing a value that is present, and never copying `sid`, `azp`, `iss`, `aud`, `exp` or `iat`. `TOK_001` when UserInfo belongs to another user, `OIDC_003` when it fails. |
| `refresh(refresh_token: &str, resource: Option<&str>) -> Result<TokenSet>` | Exchanges a refresh token. The provider rotates it on every use; concurrent callers should go through a `GrantManager`. `scope` is never sent. `OIDC_003`. |
| `logout_url(id_token_hint: Option<&str>, state: Option<&str>) -> Result<String>` | URL ending the provider session (RP-initiated logout). `OIDC_004` when the provider has no `end_session_endpoint`. |
| `revoke(token: &str, hint: Option<TokenTypeHint>) -> Result<()>` | Revokes a token. `OIDC_004` without a `revocation_endpoint`, `OIDC_003` on a refusal. |
| `introspect(token: &str, hint: Option<TokenTypeHint>) -> Result<IntrospectionResult>` | RFC 7662 introspection. `OIDC_004` without an `introspection_endpoint`, `OIDC_003` on a refusal. |
| `client_credentials(scope: Option<&str>, resource: Option<&str>) -> Result<TokenSet>` | The `client_credentials` grant for the application itself. `CFG_001` without a client secret, `OIDC_003` on a refusal. |
| `verify_jwt(token: &str, audience: &str, typ: Option<&str>) -> Result<Map<String, Value>>` | Low-level: verifies signature, issuer, audience and expiry of a JWT signed by the provider and returns its claims. Prefer `BearerVerifier` and the logout token verifier. `TOK_001`. |

`Prompt` is `Login`, `Consent`, `SelectAccount`, `Create` or `None`, with `as_str()` and `Prompt::from_wire(&str) -> Option<Prompt>`. `TokenTypeHint` is `AccessToken` or `RefreshToken`. Discovery and the signing keys are cached for an hour, and a failed discovery is not cached.

```rust
use auth_ai::{AuthAiError, AuthClient, Prompt};

async fn begin(auth: &AuthClient) -> Result<(), AuthAiError> {
    let login = auth.start_login(Some(Prompt::Login), None).await?;
    // Send the browser to `login.url`, keep `login.handshake` until it comes back.
    println!("{}", login.url);

    // On the callback, with the persisted handshake:
    // let result = auth.handle_callback(callback_url, &login.handshake).await?;
    Ok(())
}
```

## `GrantManager`

The only place that refreshes tokens. Clones share one cache. See [Sessions and grants](/docs/concepts/sessions-and-grants). Construction (`GrantManager::new` and `GrantManager::builder`) is in [Configuration](/docs/reference/configuration#other-constructors).

| Method | Description |
| --- | --- |
| `save(grant_id: &str, refresh_token: &SecretString) -> Result<()>` | Stores the refresh token obtained at sign-in, replacing any older chain, and drops the cached access tokens of the grant. |
| `has(grant_id: &str) -> Result<bool>` | Whether a refresh token is stored. |
| `get_access_token(grant_id: &str, resource: Option<&str>) -> Result<AccessToken>` | An access token narrowed to one resource, cached until the expiry skew (30 seconds by default) before it expires. `TOK_002` when there is no grant or the provider answers `invalid_grant`: the grant is then dropped. |
| `refresh_tokens(grant_id: &str) -> Result<TokenSet>` | Refreshes without narrowing and returns the whole token set, ID token included. The rotated refresh token is stored. |
| `invalidate(grant_id: &str, resource: Option<&str>)` | Synchronous. Drops a cached access token the API refused. |
| `revoke(grant_id: &str) -> Result<()>` | Revokes the refresh token at the provider, then forgets the grant even if the provider is unreachable. The provider's refusal is returned after the grant was forgotten. |

Every refresh and revocation runs on its own spawned task and is awaited: a caller that gives up cannot leave the provider with a rotated refresh token this process never stored. `AccessToken` has `access_token: SecretString` and `expires_at: i64`.

Traits and defaults:

| Name | Description |
| --- | --- |
| `GrantStore` | `async fn get(&self, grant_id: &str) -> Result<Option<SecretString>>`, `set(&self, grant_id: &str, refresh_token: &SecretString) -> Result<()>`, `delete(&self, grant_id: &str) -> Result<()>`. Implemented for `Arc<T>`. A failing store reports `SRV_001`. |
| `GrantLock` | `async fn hold(&self, grant_id: &str) -> Result<LockGuard>`. The returned `LockGuard` releases the lock when dropped; build one with `LockGuard::new(release_on_drop)`. |
| `GrantAuth` | What the manager needs of the OIDC client: `refresh` and `revoke`. Implemented by `AuthClient`. |
| `MemoryGrantStore` | In-process store, for tests and prototypes. |
| `InProcessGrantLock` | One lock per grant, dropped when idle. Covers one process only. |

Both traits use `#[async_trait]`.

## `AiClient` and `UserAi`

`AiClient::new(auth: AuthClient, grants: GrantManager)` builds the per-user clients. `for_user(grant_id: &str) -> Result<UserAi>` returns a `UserAi`, where `grant_id` is the key the refresh token was saved under (the user's `sub`). It returns `CFG_001` when the configured gateway URL cannot be used.

| Member | Description |
| --- | --- |
| `wallet: WalletClient` | A public field. |
| `resources: ResourceSharingClient` | A public field. Needs `resource_sharing(true)` in the configuration. |
| `gateway(&self) -> Result<&GatewayClient>` | Synchronous. `CFG_001` when `gateway_url` is not configured. |

## `WalletClient`

The signed-in user's own wallet, read with a token minted for the auth-service audience with the `wallet:self:read` scope. A `401` drops the cached token and retries once. All failures are `API_001` (a refusal or an unreachable auth-service) or `API_002` (an unexpected answer).

| Method | Returns | Description |
| --- | --- | --- |
| `get_account()` | `WalletAccount` | `balance`, `is_unlimited`, `can_spend`, `currency` (`Currency::Eur`). Decide with `can_spend`. |
| `get_stats(days: Option<u32>)` | `WalletStats` | Spend over `days` (1 to 90, 30 by default): `days`, `total`, `not_billed`, `calls`, `series`, `by_application`, `by_kind`, `by_model` and `daily`. |
| `get_session_usage(session_id: &str, days: Option<u32>)` | `WalletSessionUsage` | What one chat session spent, for the calling application only: `session_id`, `application_slug`, `days`, `total`, `not_billed`, `calls`, `by_model`. |
| `list_transactions(limit: Option<u32>, cursor: Option<&str>, kind: Option<WalletTransactionType>)` | `WalletTransactionPage` | Newest first, keyset-paginated: pass `next_cursor` back until it is `None`. |
| `get_topup_options()` | `TopupOptions` | `enabled`, `currency`, `min_cents`, `max_cents`. |
| `topup_url(&self) -> String` | `String` | Synchronous. The Credit tab of the user's profile. |

`WalletTransactionType` is `Topup`, `Grant`, `Refund`, `Usage`, `Adjust` or `Reversal`. A `WalletTransaction` has `id`, `kind` (the wire name is `type`), `amount`, `delta`, `balance_after`, `application_id`, `metadata` and `created_at` (an `OffsetDateTime`).

All amounts are `Amount`, an alias of `i128` micro-euros. The models serialize with the camelCase wire names, with amounts as integer strings (a JSON number cannot carry them exactly): that is what the [BFF routes](/docs/reference/web-and-axum#routes) send. `MICRO_PER_EUR` is `1_000_000`, and `format_euros(amount: Amount, fraction_digits: u8) -> Result<String>` truncates toward zero (0 to 6 digits, `CFG_001` otherwise). The per-model, per-application, per-kind and daily entry types are `ModelUsage`, `ApplicationUsage`, `KindUsage`, `DailyPoint` and `DailyUsage`.

```rust
use auth_ai::{AuthAiError, UserAi, format_euros};

async fn balance(user: &UserAi) -> Result<String, AuthAiError> {
    let account = user.wallet.get_account().await?;
    // `balance` is in micro-euros: 5_000_000 is 5 EUR.
    format_euros(account.balance, 2)
}
```

## `ResourceSharingClient`

The signed-in user's own resources and shares, reached as `ai.for_user(id)?.resources`. Every call uses a token minted for the auth-service audience with the `resources:self:manage` scope, which `resource_sharing(true)` adds at sign-in. The token belongs to the user: the application acts only on what that user owns or administers. All failures are `API_001` (a refusal or an unreachable auth-service), `API_002` (an unexpected answer) or `CFG_001` for an input refused before any request.

| Method | Returns | Description |
| --- | --- | --- |
| `list_member_applications()` | `Vec<MemberApplication>` | The applications the user may declare a resource into; `can_create` says whether they may. |
| `list_organizations()` | `Vec<Organization>` | The organizations the user belongs to, for an organization audience. |
| `list_owned()` | `Vec<Resource>` | Every resource the user owns. |
| `get(resource_id)` | `Resource` | One resource the user owns or administers. The id must be a UUID. |
| `create(&CreateResource)` | `Resource` | Declares a resource. It starts `pending_validation`; `audience` shares it in the same call. |
| `update(resource_id, &UpdateResource)` | `Resource` | Changes `display_name`, `listed` or `metadata`; at least one is required. |
| `delete(resource_id)` | `DeletedResource` | Removes it; `removed` says whether it was removed rather than disabled. |
| `request_validation(resource_id)` | `ValidationRequest` | Asks the scheme's validator to check it. |
| `list_grants(resource_id)` | `Vec<Grant>` | The grants of a resource. |
| `create_grant(resource_id, &CreateGrant)` | `Grant` | Shares a resource. A `User` subject takes an id or an e-mail, never both; `expires_at` must be in the future. |
| `revoke_grant(resource_id, grant_id)` | `Grant` | Revokes a grant. |
| `list_accessible(scheme, application_id)` | `Vec<AccessibleResource>` | Every validated resource the user may use; a listing filter, never an admission. |
| `get_catalogue()` | `Catalogue` | The applications, accessible resources and enabled schemes. |

`ResourceAudience` names who a resource is shared with at creation time: `ResourceAudience::user(id)`, `::email(address)`, `::organization(id)`, `::plan(id)` or `::everyone()`. `Resource` carries `id`, `application_id`, `application_slug`, `application_name`, `scheme`, `scheme_display_name`, `locator`, `uri`, `display_name`, `owner_type`, `owner_id`, `status`, `listed`, `metadata`, the validation times and error, and `created_at`/`updated_at`. `Grant` carries `id`, `resource_id`, `subject_type`, `subject_id`, `permission`, `expires_at`, `revoked_at`, `created_by` and `created_at`.

```rust
use auth_ai::{AuthAiError, CreateResource, ResourceAudience, UserAi};

async fn share_with_a_colleague(user: &UserAi) -> Result<(), AuthAiError> {
    let created = user
        .resources
        .create(&CreateResource {
            application_id: "1d2c3b4a-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
            scheme: "gine",
            display_name: "Firmware",
            locator: Some("job-1"),
            metadata: None,
            audience: Some(&ResourceAudience::email("colleague@example.com")),
        })
        .await?;
    println!("{} {}", created.id, created.status);
    Ok(())
}
```

## `GatewayClient`

The LiteLLM gateway on behalf of a signed-in user. The user's access token is the API key: it is minted per call, cached by the grant manager and never stored. The token is only ever sent to the gateway's origin.

| Member | Description |
| --- | --- |
| `openai_base_url(&self) -> String` | Synchronous. `<gateway_url>/v1`, the `base_url` of an OpenAI-compatible SDK. |
| `access_token() -> Result<SecretString>` | A fresh access token, for clients that sign their own requests. Fetch it again for every request: it lives one hour. `TOK_002` when the user has no usable grant. |
| `invalidate_token(&self)` | Synchronous. Drops the cached token after the gateway answered `401` to a request you signed yourself. |
| `list_models()` | `Vec<GatewayModel>` from `/v1/models`. |
| `list_agents()` | `Vec<GatewayAgent>` from `/v1/agents`. |
| `list_mcp_servers()` | `Vec<GatewayMcpServer>` from `/v1/mcp/server`. |
| `mcp_url(server_name: Option<&str>) -> Result<String>` | Synchronous. `<gateway_url>/mcp`, or `<gateway_url>/<server_name>/mcp`. A name outside `[A-Za-z0-9][A-Za-z0-9_.-]{0,127}`, or `v1`, returns `CFG_001`. |
| `post_json(path: &str, body: &serde_json::Value) -> Result<serde_json::Value>` | POSTs JSON to a gateway route and returns the parsed answer, which you validate. `CFG_001` when `path` would leave the gateway. |

The listings validate the answer and return `GW_005` when its shape is unexpected. `GatewayModel` has `id` (and optionally `object`, `created`, `owned_by`), `GatewayAgent` has `agent_id` and `agent_name`, and `GatewayMcpServer` has `server_id` and optionally `server_name`, `alias`, `description` and `transport`. Members the gateway adds are kept in `extra`.

Failures map by HTTP status, with `to_gateway_error(status: u16, body: Option<&Value>, headers: &[(String, String)]) -> AuthAiError`: `402` is `GW_001`, `429` is `GW_002`, `401` and `403` are `GW_003`, `503` is `GW_004`, anything else is `GW_005`; a network failure is `GW_004`. The gateway's own error message and `type` are kept in the error's `message` and `details`. `is_insufficient_credit(&err)` is true for a `GW_001` error; `is_insufficient_credit_status(status: u16)` is a `const fn` testing the status of an error from an OpenAI-compatible SDK for `402`.

```rust
use auth_ai::{AuthAiError, UserAi, is_insufficient_credit};
use serde_json::json;

async fn ask(user: &UserAi) -> Result<Option<String>, AuthAiError> {
    let gateway = user.gateway()?;
    let body = json!({
        "model": "gpt-x",
        "messages": [{ "role": "user", "content": "Hello" }],
    });
    match gateway.post_json("/v1/chat/completions", &body).await {
        Ok(answer) => Ok(answer["choices"][0]["message"]["content"]
            .as_str()
            .map(str::to_owned)),
        // The wallet is empty: send the user to `user.wallet.topup_url()`.
        Err(err) if is_insufficient_credit(&err) => Ok(None),
        Err(err) => Err(err),
    }
}
```

## Claims, helpers and `SessionUser`

| Export | Description |
| --- | --- |
| `IdTokenClaims` | `iss`, `sub`, `aud: Audience`, `exp`, `iat`, then `roles`, `permissions`, `features`, `plan`, `org_id`, `sid`, `azp` and the profile claims `name`, `picture`, `given_name`, `family_name`, `company`, `updated_at`, `email`, `email_verified`, `phone_number`, all `Option`s. Claims the SDK does not model are kept in `extra`. |
| `AccessTokenClaims` | The same base, with a required `azp`, a `scope: Option<String>` (space-separated) and no profile claims. |
| `UserInfoClaims` | The standard UserInfo claims (`sub` is required), with `address: Option<AddressClaim>` and the entitlement claims. |
| `Audience` | `One(String)` or `Many(Vec<String>)`; `to_vec()` and `contains(&str)`. |
| `FeatureValue` | `Bool`, `Int(i64)`, `Float(f64)` or `Text(String)`; `is_enabled()` is false for `false`, `0` and `""`. |
| `EntitlementClaims` | The trait the helpers below accept: `roles()`, `permissions()` and `features()`. Implemented by the three claim types. |
| `has_role`, `has_permission`, `has_feature`, `get_feature` | See [Entitlements](/docs/concepts/entitlements). `has_permission(claims, resource, action)` takes a `PermissionAction` (`Read` or `Write`); `Write` implies `Read`. `get_feature` returns `Option<&FeatureValue>`. |
| `SessionUser`, `to_session_user(&IdTokenClaims)` | The browser-safe user: `sub`, `name`, `email`, `email_verified`, `picture`, `roles`, `permissions`, `features`, `plan`, `org_id`, with absent entitlements as empty values. Serializes in camelCase without the `None` members; `to_json()` returns it as a `serde_json::Value`. |

## Errors

| Export | Description |
| --- | --- |
| `AuthAiError` | The error of every failure: `code()`, `message()`, `details()`, `detail(key)`, `oauth_error()` and the cause through `std::error::Error::source()`. `to_public_json()` returns `{ "code", "message" }` with the registry's generic message; `to_json()` adds the detailed `message` and the `details`. It implements `std::error::Error` and `Display` (`"TOK_002: No usable grant for this user: sign in again"`). |
| `ErrorCode` | The `#[non_exhaustive]` enum of the codes (`ErrorCode::Tok002`). `as_str()`, `default_message()`, `from_wire(&str) -> Option<ErrorCode>`, `ErrorCode::ALL`, and `error()` to build an `AuthAiError` of that code. |
| `AuthAiError` builders | `AuthAiError::new(code)`, `.with_message(..)`, `.with_detail(key, value)` and `.with_source(cause)`. Use them in your own stores and adapters so that a failure carries a registry code. |
| `PublicError` | `code` and the generic `message`: what `to_public()` returns. |
| `DetailValue`, `ErrorDetails` | A detail is a `Str`, `Int`, `Float` or `Bool`; `ErrorDetails` is a `BTreeMap<&'static str, DetailValue>`. `DetailValue::as_str()` reads a string detail. |

The codes are listed in [Error codes](/docs/reference/error-codes).
