## `AuthHandlers`

`auth_ai::web` exports `AuthHandlers`, built synchronously with the options in [Configuration](/docs/reference/configuration#authhandlers). The handlers speak `WebRequest` and `WebResponse`, so any framework can mount them: the axum adapter is [below](#axum-adapter), the others are in [Other frameworks](/docs/guides/backend/other-frameworks). `AuthHandlers` is cheap to clone: clones share their state.

| Member | Description |
| --- | --- |
| `handle(&self, request: &WebRequest) -> Option<WebResponse>` | Async. Serves the routes below `base_path`. Returns `None` for any other path or unknown route, so your application can answer. |
| `get_session(&self, request: &WebRequest) -> Result<Option<Session>>` | Async. The signed-in `Session` of a request, with claims renewed when due, or `None` when signed out. Two simultaneous requests of one session share a single renewal. |
| `require_session(&self, request: &WebRequest) -> Result<Session>` | Async. Like `get_session`, returning `SES_001` when signed out. |
| `origin(&self) -> &str` | Synchronous. The origin the SDK builds URLs on: that of `redirect_uri`, never a request header. |
| `base_path(&self) -> &str` | Synchronous. The resolved base path. |
| `on_error(&self) -> Option<&ErrorCallback>` | Synchronous. The failure callback, for adapters that answer errors themselves. |

### Routes

The path of a route is `<base_path><route>`; the table assumes the default `/auth`.

| Route | Method | Behaviour |
| --- | --- | --- |
| `/login` | `GET` | Sealed handshake cookie, then `302` to auth-service. Query: `next` (same-origin path, falls back to `default_redirect`) and `prompt` (`login`, `consent`, `select_account`, `create` or `none`; anything else is ignored). |
| `/callback` | `GET` | Completes the sign-in, stores the grant, creates the session, then `303` to `next` with the session cookie. Any failure answers `403` `SES_005`, or `303` to `<error_redirect>?error=SES_005`. |
| `/me` | `GET` | `{ "user": SessionUser, "expiresAt": … }`, or `401` `SES_001`. |
| `/logout` | `POST` | Refused with `403` `SES_004` when cross-site. Otherwise ends the current session, revokes the grant if the user has no other session, clears the session cookie, sets the sealed logout cookie, then answers `{ "logoutUrl": … }` (`Accept: application/json`) or `303` to the provider's logout URL (or the `next` path, or `default_redirect`, when the provider has no end-session endpoint). Query: `next`. Without a session it still answers the provider's logout URL, built without `id_token_hint`: the provider asks the user to confirm, then ends its single sign-on session for every application. `logoutUrl` is `null` only when the provider advertises no end-session endpoint. |
| `/logout/callback` | `GET` | The post-logout landing route: clears the sealed logout cookie and answers `303` to the `next` path it carried (`default_redirect` when the cookie is missing or unreadable, so a user is never stranded). Register `<origin><base_path>/logout/callback` as the application's `post_logout_redirect_uri`. |
| `/backchannel-logout` | `POST` | See [Server API](/docs/reference/server-api#back-channel-logout). Ends every session bound to the logout token's `sid`. |
| `/wallet` | `GET` | With the `ai` option. The wallet account (`balance`, `isUnlimited`, `canSpend`, `currency`) plus `topupUrl`. |
| `/wallet/stats` | `GET` | With the `ai` option. Wallet statistics; query `days` is an integer from 1 to 90, otherwise `400` `REQ_001`. |
| `/models` | `GET` | With the `ai` option. `{ "models": […] }` from the gateway. |

A route called with another method answers `405` with `Allow`. Every JSON response carries `Cache-Control: no-store`. The JSON uses the camelCase wire names that the [TypeScript client](/docs/guides/frontend/use-the-typescript-client) reads.

### Failure answers

Failures use `{ "error": { "code", "message" } }` with the registry's generic message. Statuses:

| Status | Codes |
| --- | --- |
| `400` | `REQ_001`, `SES_002`, `OIDC_002` |
| `401` | `SES_001`, `TOK_001`, `TOK_002`, `TOK_003` |
| `402` | `GW_001` |
| `403` | `SES_004`, `SES_005`, `TOK_004`, `GW_003` |
| `429` | `GW_002` |
| `501` | `OIDC_004` |
| `502` | `OIDC_001`, `OIDC_003`, `API_001`, `API_002`, `GW_005` |
| `503` | `GW_004` |
| `500` | every other code (`CFG_001`, `SES_003`, `SRV_001`) |

An `AuthAiError` answered with a status of 500 or above (provider or API unreachable, unexpected answer, a failing store) is passed to `on_error`. The full table with causes and remedies is in [Error codes](/docs/reference/error-codes). The table is `status_for(code: ErrorCode) -> u16`, a `const fn`; `error_response(err: &AuthAiError, on_error: Option<&ErrorCallback>, headers: Vec<(String, String)>) -> WebResponse` builds such an answer. Both are exported from `auth_ai::web`.

### Cookies

| Cookie | Name on HTTPS | Name on loopback HTTP | Lifetime | Content |
| --- | --- | --- | --- | --- |
| Session | `__Host-aai_session` | `aai_session` | `session_ttl_seconds` | A random 256-bit id, base64url. |
| Sign-in | `__Host-aai_login` | `aai_login` | 600 seconds (`HANDSHAKE_TTL_SECONDS`) | The sealed handshake (`state`, `nonce`, `codeVerifier`, `next`). Cleared after the callback. |
| Sign-out | `__Host-aai_logout` | `aai_logout` | 600 seconds | The sealed `state` and `next` path. Cleared by `/logout/callback`. |

All are `Path=/`, `HttpOnly`, `SameSite=Lax`, plus `Secure` on HTTPS. The name has the `__Host-` prefix exactly when `redirect_uri` is HTTPS.

The helpers behind them are exported from `auth_ai::web`:

| Function | Description |
| --- | --- |
| `cookie_name(base: &str, secure: bool) -> String` | Adds the `__Host-` prefix when `secure`. |
| `parse_cookies(header: Option<&str>) -> HashMap<String, String>` | The cookies of a `Cookie` header. The first occurrence of a name wins. |
| `serialize_cookie(name: &str, value: &str, max_age_seconds: i64, secure: bool) -> Result<String>` | A hardened `Set-Cookie` value. `CFG_001` when the value holds a character outside letters, digits, `.`, `_`, `~` and `-`, or the name (without its `__Host-` prefix) holds one outside letters, digits, `_` and `-`. |
| `clear_cookie(name: &str, secure: bool) -> Result<String>` | A `Set-Cookie` value that removes the cookie (`Max-Age=0`). |

### Sealed cookies

`seal` and `unseal` encrypt and authenticate a short-lived JSON value: a compact JWE (`alg` `dir`, `enc` `A256GCM`) carrying `{ data, iat, exp }`. The wire form is shared with the TypeScript and Python SDKs, so a backend in another language with the same secret reads what this one sealed.

| Item | Description |
| --- | --- |
| `derive_seal_key(secret: &str) -> Result<SealKey>` | Derives the AES-256 key from the application's secret. `CFG_001` when it is shorter than `MIN_SECRET_LENGTH` (32 characters). |
| `SealKey` | The key. Never prints, zeroed on drop. |
| `seal(key: &SealKey, data: &serde_json::Value, ttl_seconds: i64) -> Result<String>` | The sealed token. `SRV_001` when the random generator or the cipher fails. |
| `unseal<T: DeserializeOwned>(key: &SealKey, token: &str) -> Result<T>` | The value, deserialized as `T`. `SES_002` for any tampered, expired or malformed token. |

### Redirects and cross-site requests

| Function | Description |
| --- | --- |
| `safe_redirect_path(candidate: Option<&str>, fallback: &str) -> String` | Reduces a redirect target taken from a request to a same-origin path, or returns `fallback` for `None`, an absolute URL, a protocol-relative one (`//host`), a backslash, a control character or anything odd. Use it for your own `next` parameters. |
| `is_cross_site(request: &WebRequest, expected_origin: &str) -> bool` | Whether a browser sent this state-changing request from another site: an `Origin` that differs, or a `Sec-Fetch-Site` other than `same-origin` or `none`. A request with neither header (a non-browser client) passes. |

## Session and `SessionStore`

```rust
#[derive(Debug, Clone)]
pub struct Session {
    pub id: String,                 // SHA-256 of the cookie value, base64url
    pub user_id: String,            // the provider's `sub`; also the grant id
    pub session_id: Option<String>, // the provider session (`sid`)
    pub claims: IdTokenClaims,
    pub id_token: SecretString,     // hint for the provider's logout endpoint
    pub created_at: i64,            // Unix seconds
    pub expires_at: i64,            // absolute end of the session
    pub renew_at: i64,              // next claims renewal
}
```

This is `auth_ai::web::Session`, shown for reference: import the real type instead of redefining it.

`SessionStore` is an `#[async_trait]` trait with six methods, all returning `Result<_, AuthAiError>`:

| Method | Description |
| --- | --- |
| `create(&self, session: &Session)` | Stores a new session. |
| `get(&self, session_key: &str) -> Option<Session>` | `None` for an unknown **or expired** session. |
| `update(&self, session: &Session)` | Replaces a session that still exists. |
| `delete(&self, session_key: &str)` | Removes a session. |
| `delete_by_provider_session(&self, session_id: &str) -> Vec<Session>` | Removes and returns every session of a provider session. |
| `count_by_user(&self, user_id: &str) -> usize` | The number of live sessions of a user. |

`MemorySessionStore` is the in-process implementation, for demos and tests. A failing store reports `SRV_001`. The contracts are detailed in [Implement the stores](/docs/guides/backend/custom-stores).

## `WebRequest` and `WebResponse`

Exported from the crate root (`auth_ai::WebRequest`, `auth_ai::WebResponse`). Both are plain structs (`Debug`, `Clone`, `PartialEq`).

| Type | Members |
| --- | --- |
| `WebRequest` | `method: String` (upper case), `url: String` (absolute; the SDK reads only its path and query), `headers: Vec<(String, String)>` (lowercase names), `body: Vec<u8>`. `WebRequest::new(method, url)` upper-cases the method; `.with_header(name, value)`, `.with_body(bytes)` and `header(name)` complete it. |
| `WebResponse` | `status: u16`, `headers: Vec<(String, String)>` (so `Set-Cookie` can repeat), `body: Vec<u8>`. `WebResponse::new(status, headers)`, then `header(name)`, `header_values(name)` and `json() -> Option<Value>` read it. |

`json_response(body: &Value, status: u16, headers: Vec<(String, String)>) -> WebResponse` and `redirect_response(location: &str, status: u16, headers: Vec<(String, String)>) -> WebResponse` build answers that carry `Cache-Control: no-store` (`NO_STORE`).

## axum adapter

`auth_ai::axum` needs the `axum` cargo feature and your own dependency on `axum` 0.8 (the SDK enables only its `tokio` feature, so add `http1` or `http2`, and `json`, as your server needs). The application state must give out the handlers: implement `FromRef<YourState> for AuthHandlers`, or use `AuthHandlers` as the state.

| Export | Description |
| --- | --- |
| `auth_router::<S>(handlers: AuthHandlers) -> Router<S>` | Serves every route below `handlers.base_path()` for any method; an unknown route below it answers `404`. **Mount it at the root of your application** (`merge`, not `nest`): the path the handlers see must include the base path. |
| `AuthSession(pub Session)` | Extractor for a signed-in request; a signed-out one is answered `401` `SES_001` by the extractor itself, and a failing store or renewal with the status of its code. |
| `OptionalAuthSession(pub Option<Session>)` | Extractor that yields `None` when signed out. A failing store or renewal is still answered. |
| `AuthError(pub AuthAiError)` | A response type: answers the error with the public envelope and the status of its code. Implements `IntoResponse` and `From<AuthAiError>`, so `?` works in a route returning `Result<_, AuthError>`. |
| `to_web_request(request: Request<Body>, origin: &str, with_body: bool) -> Result<WebRequest, AuthAiError>` | Builds a `WebRequest` on `origin`, not on the `Host` header. The body is read (capped at 16 KiB, `REQ_001` beyond) only when asked and for a method other than `GET`: the session extractors leave it to your route. |
| `into_response(response: WebResponse) -> Response` | Converts a `WebResponse` to an axum response, keeping repeated headers such as `Set-Cookie` apart. |

The extractors read the session without touching the body, so they compose with `Json` and the other body extractors.

```rust
use auth_ai::AiClient;
use auth_ai::axum::{AuthError, AuthSession, OptionalAuthSession, auth_router};
use auth_ai::web::AuthHandlers;
use axum::extract::{FromRef, State};
use axum::routing::get;
use axum::{Json, Router};
use serde_json::{Value, json};

#[derive(Clone)]
struct AppState {
    handlers: AuthHandlers,
    ai: AiClient,
}

impl FromRef<AppState> for AuthHandlers {
    fn from_ref(state: &AppState) -> Self {
        state.handlers.clone()
    }
}

// Optional session: a page that renders for everyone but differently when signed in.
async fn home(OptionalAuthSession(session): OptionalAuthSession) -> Json<Value> {
    Json(json!({ "signedIn": session.is_some() }))
}

// A gateway error such as `GW_001` becomes the public envelope with its status (402).
async fn models(
    State(state): State<AppState>,
    AuthSession(session): AuthSession,
) -> Result<Json<Value>, AuthError> {
    let user = state.ai.for_user(&session.user_id)?;
    let listed = user.gateway()?.list_models().await?;
    Ok(Json(json!({ "models": listed })))
}

fn app(state: AppState) -> Router {
    Router::new()
        .merge(auth_router::<AppState>(state.handlers.clone()))
        .route("/", get(home))
        .route("/api/models", get(models))
        .with_state(state)
}
```
