Everything below is exported from `auth_ai::server`. It needs no web framework and no cargo feature.

## Bearer verification

`BearerVerifier::new(auth: AuthClient, audience: impl Into<String>) -> Result<BearerVerifier>` verifies JWT access tokens minted for **your API**. `audience` must be an absolute URL (otherwise `CFG_001`) and must appear in the token's `aud`. Opaque tokens are refused. The verifier is cheap to clone.

| Member | Description |
| --- | --- |
| `verify(&self, token: &str) -> Result<VerifiedAccessToken>` | Verifies a raw JWT: signature, issuer, audience and expiry, then that it is bound to a client (`azp`). Failures are `TOK_001`. |
| `verify_header(&self, authorization: Option<&str>) -> Result<VerifiedAccessToken>` | Same, from the value of an `Authorization: Bearer …` header. A missing or malformed header returns `TOK_003`. |

Related functions:

| Function | Description |
| --- | --- |
| `extract_bearer_token(authorization: Option<&str>) -> Result<&str>` | Returns the token of a bearer `Authorization` header, or `TOK_003`. |
| `require_scopes(token: &VerifiedAccessToken, required: &[&str]) -> Result<()>` | Returns `TOK_004` (with `details["missing"]`, a space-separated list) unless the token carries every listed scope. |

`VerifiedAccessToken` is a plain struct (`Debug`, `Clone`):

| Field | Description |
| --- | --- |
| `user_id: Option<String>` | The end user's `sub`, or `None` for a `client_credentials` token (where `sub` is the client id itself). |
| `client_id: String` | The OAuth client the token was issued to (`azp`). |
| `scopes: Vec<String>` | The granted scopes. |
| `audiences: Vec<String>` | The `aud` values. |
| `claims: AccessTokenClaims` | The verified claims. |

```rust
use auth_ai::AuthAiError;
use auth_ai::server::{BearerVerifier, require_scopes};

async fn caller(
    verifier: &BearerVerifier,
    authorization: Option<&str>,
) -> Result<String, AuthAiError> {
    let token = verifier.verify_header(authorization).await?;
    require_scopes(&token, &["roles"])?;
    // A machine caller has no user id: fall back to its client id.
    Ok(token.user_id.unwrap_or(token.client_id))
}
```

See [Protect an API](/docs/guides/backend/protect-an-api) for a complete axum example.

## Protected-resource metadata

| Function | Description |
| --- | --- |
| `protected_resource_metadata(auth: &AuthClient, resource: &str, scopes_supported: Option<&[&str]>) -> serde_json::Value` | The RFC 9728 document: `resource`, `authorization_servers` (the issuer), `bearer_methods_supported` (`["header"]`) and, when given, `scopes_supported`. |
| `protected_resource_metadata_path(resource: &str) -> Result<String>` | Where to serve it: `/.well-known/oauth-protected-resource` followed by the path of `resource`. `CFG_001` when `resource` is not an absolute URL. |
| `bearer_challenge(resource_metadata_url: &str, error: Option<BearerError>, scope: Option<&str>) -> Result<String>` | The value of the `WWW-Authenticate` header of a `401` or `403`. `CFG_001` for a value containing `"`, `\`, CR or LF. |

`BearerError` is `InvalidToken` (answer `401`) or `InsufficientScope` (answer `403`).

## Back-channel logout

`BackchannelLogoutHandler::new(auth: AuthClient, on_logout: LogoutCallback)` handles the endpoint auth-service calls when a user signs out. `AuthHandlers` mounts one at `/backchannel-logout` for you; build your own only when you do not use the sign-in handlers.

`handler.handle(&WebRequest).await` returns a `WebResponse`. It is called without cookies or credentials, so mount it outside any session or CSRF protection.

| Part | Description |
| --- | --- |
| `on_logout` | A `LogoutCallback`: `Arc<dyn Fn(BackchannelLogoutEvent) -> BoxFuture<'static, Result<()>> + Send + Sync>`. Called with a `BackchannelLogoutEvent` (`sid`, `sub`): end every local session whose stored `sid` equals this one. |
| `.replay_store(Arc<dyn ReplayStore>)` | Defaults to a `MemoryReplayStore`. Share it across replicas. |
| `.allow_missing_typ(bool)` | Accepts a token without a `typ` header. Only for a known non-conforming provider; off by default. |
| `.on_error(ErrorCallback)` | Receives every rejected token and failed callback: the response carries no detail. |

Answers:

| Status | When |
| --- | --- |
| `200` | The logout token is valid and `on_logout` succeeded. |
| `400` with `{"error": "invalid_request"}` | The content type is not `application/x-www-form-urlencoded`, the body is larger than 16 KiB (`MAX_BODY_BYTES`), `logout_token` is missing, or the token is invalid or replayed. |
| `500` with `{"error": "server_error"}` | `on_logout` failed. |
| `405` with `Allow: POST` | Any other method. |

`verify_logout_token(auth: &AuthClient, token: &str, replay_store: &dyn ReplayStore, allow_missing_typ: bool) -> Result<LogoutTokenClaims>` is the verifier behind it. It requires a `logout+jwt` (`LOGOUT_TOKEN_TYP`) for your client id with the back-channel logout event (`LOGOUT_EVENT`), a `jti`, a `sid` and a `sub`, no `nonce`, a lifetime of at most 600 seconds (`MAX_LOGOUT_TOKEN_LIFETIME_SECONDS`) and an `iat` not in the future, and claims the `jti` once. Failures are `TOK_001`. `LogoutTokenClaims` has `sid`, `sub`, `jti`, `iat` and `exp`.

`ReplayStore` is a trait with one method, `async fn claim(&self, jti: &str, expires_at: f64) -> Result<bool>`: `true` the first time, `false` on a replay. `MemoryReplayStore` is the in-process implementation. See [Implement the stores](/docs/guides/backend/custom-stores).

## `MachineApi`

`MachineApi::new(auth: &AuthClient) -> Result<MachineApi>` calls the auth-service REST API **as your application**, with `client_credentials` tokens minted from its own secret. It returns `CFG_001` without a client secret. The scopes `billing:read`, `consumption:read`, `consumption:write` and `resources:validate` are granted to new confidential applications; `resources:authorize` is a platform scope that only a superadmin grants. A refused scope returns `TOK_004` with `details["scope"]`.

It has three public fields, `billing`, `consumption` and `resources` (fields, not methods: `machine.resources.authorize(..)`). The API errors are `API_001` (auth-service refused, or is unreachable) and `API_002` (an unexpected answer). See [Billing and consumption](/docs/guides/ai-and-billing/billing-and-consumption) and [Resource sharing](/docs/guides/ai-and-billing/resource-sharing).

### `machine.billing`

| Method | Returns | Description |
| --- | --- | --- |
| `get_subscription(user_id: &str)` | `Option<SubscriptionView>` | `None` when the user has no subscription. Fields: `plan` (`PlanRef` with `id`, `name`), `is_active`, `expires_at`, `stripe_status`, `current_period_start`, `current_period_end`, `cancel_at_period_end`, `canceled_at`. |
| `get_usage(user_id: &str)` | `UsageView` | `period_start` and `features`: each `FeatureUsage` has `feature_key`, `unit`, `usage_limit` (`-1.0` is unlimited), `used` and `remaining` (`None` when unlimited). |
| `list_invoices(user_id: &str, limit: Option<u32>, cursor: Option<&str>)` | `InvoicePage` | `items` (`InvoiceView`) and `next_cursor`. Newest first; `limit` is 1 to 100. |

An `InvoiceView` has `id`, `status`, `billing_reason`, `currency`, `amount_due`, `amount_paid`, `amount_remaining` (cents, `i64`), `period_start`, `period_end`, `created_at`, `hosted_invoice_url` and `invoice_pdf`.

### `machine.consumption`

| Method | Returns | Description |
| --- | --- | --- |
| `report(user_id: &str, key: &str, value: impl Into<ConsumptionValue>, idempotency_key: Option<&str>)` | `ConsumptionResult` | Reports `value` units of `key`. `aggregate` is the running total (`ConsumptionTotal`: `key`, `total` as a decimal string) and `metered` is `true` when the key prices a metered feature. |
| `list_aggregates(user_id: &str)` | `Vec<ConsumptionAggregate>` | Every running total of a user: `key`, `total` and `updated_at`. |
| `get_aggregate(user_id: &str, key: &str)` | `ConsumptionAggregate` | One running total. Returns `API_001` with `details["apiCode"]` `CONS_003` when the key was never reported. |

`ConsumptionValue` is `Int(i64)` or `Float(f64)`, and converts from `i64`, `i32`, `u32` and `f64`; a value may be negative to credit back. `report` validates before sending and returns `CFG_001` for an empty `user_id`, a `key` that is not 1 to 64 characters of `a-zA-Z0-9.`, a non-finite `value`, or an `idempotency_key` that is empty or longer than 200 characters once trimmed.

```rust
use auth_ai::AuthAiError;
use auth_ai::server::MachineApi;

async fn export_done(machine: &MachineApi, user_id: &str, job: &str) -> Result<(), AuthAiError> {
    let result = machine
        .consumption
        .report(user_id, "exports", 1_i64, Some(job))
        .await?;
    println!("{} {}", result.aggregate.total, result.metered);
    Ok(())
}
```

### `machine.resources`

Resource sharing for an adapter service or an application that owns a resource scheme. auth-service stays the decision point; these calls ask it. They need an auth-service with `RESOURCE_SHARING_ENABLED` on: otherwise the routes do not exist and the call returns `API_001` (`details["status"]` `404`). See [Resource sharing](/docs/guides/ai-and-billing/resource-sharing).

| Method | Scope | Returns | Description |
| --- | --- | --- | --- |
| `authorize(&AuthorizeRequest)` | `resources:authorize` | `AuthorizeDecision` | Whether a user may use a resource: `Allowed(Allowed)` or `Denied`. `Allowed` has `resource_id`, `resource_uri`, `application_slug`, `owner_type` (`OwnerType::User` or `Application`), `owner_id` and `access_kind` (`AccessKind::Owner` or `Grant`); `Denied` carries nothing else. `decision.allowed()` returns the `Option<&Allowed>`. |
| `list_accessible(subject_id: &str, scheme: Option<&str>)` | `resources:authorize` | `Vec<AccessibleResource>` | Every validated resource the user may use, across applications. A listing filter, never an admission. |
| `validate(resource_id: &str, result: ValidationResult, reason: Option<&str>, evidence: Option<&Map<String, Value>>)` | `resources:validate` | `ResourceState` | The outcome of your ownership check: `result` is `ValidationResult::Validated` or `ValidationFailed`. `ResourceState` has `id`, `uri`, `status` (`ResourceStatus`) and `validation_error`. |
| `invalidate(resource_id: &str, reason: &str)` | `resources:validate` | `ResourceState` | Disables a resource whose ownership was lost. |
| `record_usage(&UsageRecord)` | `resources:usage:write` | `UsageReceipt` | Reports what a provider billed for a resource. `UsageReceipt` has `usage` (`RecordedUsage`: `id`, `resource_id`, `request_id`, `occurred_at`) and `replayed`. |

The scope constants are `AUTHORIZE_SCOPE`, `VALIDATE_SCOPE` and `USAGE_SCOPE`.

`AuthorizeRequest<'a>` has `subject_id`, `client_id`, `resource_uri`, `audience` (all `&str`), `request_id: Option<&str>` and `source: Option<EventSource>` (`Gateway`, `Ssh`, `External` or `Api`; `Gateway` when unset). It implements `Default`. `ResourceStatus` is `PendingValidation`, `ValidationFailed`, `Validated` or `Disabled`. An `AccessibleResource` has `resource_id`, `resource_uri`, `scheme`, `display_name`, `application_id`, `application_slug`, `application_name`, `owner_type`, `owner_id`, `access_kind` and, for a grant, `grant_subject_type` (`GrantSubjectType::User`, `Organization`, `Plan` or `Everyone`).

Every input is validated before anything is sent and returns `CFG_001` otherwise: `resource_id` is a UUID, `subject_id` and `client_id` are 1 to 256 characters, `resource_uri` is 3 to 512 characters, `audience` is 1 to 2048, `scheme` matches `^[a-z][a-z0-9]{0,49}$`, and `reason` is at most 500 characters after trimming (non-empty for `invalidate`). An `authorize` answer that is neither a known `deny` nor a complete `allow` returns `API_002`: treat every returned error as a denial. `validate` and `invalidate` are refused with `API_001` (`details["apiCode"]` `AUTH_011`) when your client is not the validator bound to the resource's scheme.

`UsageRecord<'a>` has `subject_id`, `client_id`, `resource_id`, `resource_uri`, `request_id` (all `&str`), `occurred_at: SystemTime`, `source: UsageSource` (`Provider` or `Unsupported`), `cost_usd: Option<&str>`, and `prompt_tokens`, `completion_tokens`, `total_tokens: Option<u64>`.

`record_usage` is the only accounting write the SDK exposes: auth-service owns accounting and the reads stay with it. It needs `resources:usage:write`, which is granted to the platform's metering components only, never by default. `request_id` is the event's trusted identifier (64 lowercase hex characters) and makes the call idempotent: a replay answers `replayed: true`. A payload that conflicts with the stored event returns `API_001` with `details["apiCode"]` `RES_012`; a caller with no access to the resource gets `RES_011`. It returns `CFG_001` before any request for an `occurred_at` outside the window (five minutes ahead, 30 days back), a `cost_usd` that is not a plain decimal (no sign, no exponent, no leading zero, a fractional part of 1 to 18 digits at most) or is missing for `Provider` usage, or any cost or token on `Unsupported` usage.

```rust
use std::time::SystemTime;

use auth_ai::AuthAiError;
use auth_ai::server::{MachineApi, UsageRecord, UsageSource};

async fn meter(
    machine: &MachineApi,
    subject_id: &str,
    client_id: &str,
    resource_id: &str,
    event_id: &str,
) -> Result<bool, AuthAiError> {
    let receipt = machine
        .resources
        .record_usage(&UsageRecord {
            subject_id,
            client_id,
            resource_id,
            resource_uri: "llm://acme/gpt-x",
            request_id: event_id,
            occurred_at: SystemTime::now(),
            source: UsageSource::Provider,
            cost_usd: Some("0.0042"),
            prompt_tokens: Some(120),
            completion_tokens: Some(30),
            total_tokens: Some(150),
        })
        .await?;
    Ok(receipt.replayed)
}
```
