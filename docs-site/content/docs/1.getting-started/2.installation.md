## Requirements

- Rust **1.89** or later (`rust-version` is `1.89`, edition 2024). Continuous integration runs on Rust 1.89.0, the minimum supported version, and on stable.
- A Tokio application: the SDK is async only, has no blocking facade, and spawns the tasks that must not be interrupted half-way (a refresh-token rotation, a revocation) on the Tokio runtime.
- A C toolchain (`cc`) to build `aws-lc-sys`, the cryptography library behind `aws-lc-rs`.
- A CIRCLE auth-service instance and an application registered in it. See [Register the application](/docs/getting-started/register-the-application).

## Install

::code-group

```sh [cargo add]
cargo add auth-ai
```

```toml [Cargo.toml]
[dependencies]
auth-ai = "0.1"
```

::

See [Release channels](/docs/project/release-channels) for how versions reach crates.io, including how to install a pre-release.

The SDK depends on `reqwest` (`0.13`, with rustls, HTTP/2, gzip and brotli), `aws-lc-rs` (`1.19`), `serde` and `serde_json`, `tokio` (`1.54`), `url`, `thiserror`, `zeroize` and a few small utilities, which cargo resolves for you. Every direct runtime dependency is permissively licensed.

## Cargo features

The framework adapter needs a framework. It is behind a feature that is off by default:

| Feature | Enables | Use it for |
| --- | --- | --- |
| `axum` | `axum` 0.8 and the `auth_ai::axum` module | axum applications. |

::code-group

```sh [cargo add]
cargo add auth-ai --features axum
```

```toml [Cargo.toml]
[dependencies]
auth-ai = { version = "0.1", features = ["axum"] }
```

::

Without the feature, `auth_ai`, `auth_ai::web` and `auth_ai::server` work as they are; only `auth_ai::axum` imports axum. The SDK does not install a runtime or a server: add `tokio` with the features you need (`macros` and `rt-multi-thread` for `#[tokio::main]`, `net` to listen) and your own HTTP server, for example `axum::serve`.

## Import paths

```rust
// Core: OIDC client, grants, AI clients, claims helpers, errors
use auth_ai::{AiClient, AuthClient, AuthClientConfig, GrantManager, MemoryGrantStore};

// Framework-agnostic request and response types
use auth_ai::{WebRequest, WebResponse};

// Backend-for-frontend handlers and the session store
use auth_ai::web::{AuthHandlers, MemorySessionStore, Session, SessionStore};

// axum adapter (needs the axum feature)
use auth_ai::axum::{AuthError, AuthSession, OptionalAuthSession, auth_router};

// Bearer verification, back-channel logout, protected-resource metadata, machine API
use auth_ai::server::{BearerVerifier, MachineApi, require_scopes};
```

The installed version is available as `auth_ai::VERSION`. The full exports of each module are in the [Reference](/docs/reference/core-api) and on [docs.rs](https://docs.rs/auth-ai).
