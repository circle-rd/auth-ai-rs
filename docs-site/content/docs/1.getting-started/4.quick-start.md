This page builds the smallest working backend: sign-in, session cookie, `/auth/me` and one protected route. It uses in-memory stores, which are only fit for a demo or a single instance: see [Production checklist](/docs/guides/operations/production-checklist) before deploying.

## Prerequisites

- The SDK [installed](/docs/getting-started/installation) with the `axum` feature, plus `axum`, `tokio` (with `macros`, `rt-multi-thread` and `net`) and `serde_json`.
- An application [registered in auth-service](/docs/getting-started/register-the-application) with the redirect URI `https://app.example.com/auth/callback`, the post-logout redirect URI `https://app.example.com/auth/logout/callback`, and a back-channel logout URI `https://app.example.com/auth/backchannel-logout`.
- Three values in your environment: `AUTH_ISSUER` (the auth-service URL), `AUTH_CLIENT_SECRET` and `AUTH_COOKIE_SECRET` (at least 32 random characters, for example `openssl rand -base64 48`).

## The server

```rust [src/main.rs]
use std::sync::Arc;

use auth_ai::axum::{AuthSession, auth_router};
use auth_ai::web::{AuthHandlers, MemorySessionStore, SessionStore};
use auth_ai::{AuthClient, AuthClientConfig, GrantManager, MemoryGrantStore};
use axum::routing::get;
use axum::{Json, Router};
use serde_json::{Value, json};

async fn profile(AuthSession(session): AuthSession) -> Json<Value> {
    Json(json!({
        "sub": session.claims.sub,
        "roles": session.claims.roles.unwrap_or_default(),
    }))
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // An unset variable stops the process: without a client secret the SDK
    // would silently act as a public client.
    let config = AuthClientConfig::builder(
        std::env::var("AUTH_ISSUER")?,
        "my-app",
        "https://app.example.com/auth/callback",
    )
    .client_secret(std::env::var("AUTH_CLIENT_SECRET")?)
    .post_logout_redirect_uri("https://app.example.com/auth/logout/callback")
    .build()?;
    let auth = AuthClient::new(config)?;
    let grants = GrantManager::new(auth.clone(), MemoryGrantStore::new());
    let sessions: Arc<dyn SessionStore> = Arc::new(MemorySessionStore::new());
    let handlers =
        AuthHandlers::builder(auth, grants, sessions, std::env::var("AUTH_COOKIE_SECRET")?).build()?;

    let app = Router::new()
        .merge(auth_router::<AuthHandlers>(handlers.clone()))
        .route("/api/profile", get(profile))
        .with_state(handlers);
    axum::serve(tokio::net::TcpListener::bind("0.0.0.0:3000").await?, app).await?;
    Ok(())
}
```

Run it with `cargo run`.

`AuthClientConfig::builder` takes the issuer, the client id and the redirect URI, and `build()` validates the configuration: any invalid value (a trailing slash on `gateway_url`, a non-HTTPS URL, a missing `openid` scope, an empty client secret…) returns an `AuthAiError` with the code `CFG_001`, which names every invalid option. `AuthHandlers::builder(...).build()` also checks that the path of `redirect_uri` is `<base_path>/callback`, and that the cookie secret holds at least 32 characters; `base_path` defaults to `/auth`. Set `post_logout_redirect_uri` to the absolute URL `<origin><base_path>/logout/callback` (for example `https://app.example.com/auth/logout/callback`) so the provider returns to the route the SDK serves. The `AuthClient` is cheap to clone and shares one HTTP client, discovery cache and key cache between its clones; there is nothing to close.

## What you get

`auth_router` serves six routes below `/auth`; return `Result<_, AuthError>` from your own routes to answer an `AuthAiError` with the public error envelope:

| Route | Method | What it does |
| --- | --- | --- |
| `/auth/login` | `GET` | Redirects to auth-service. Accepts `?next=/path` (same-origin paths only) and `?prompt=`. |
| `/auth/callback` | `GET` | Completes the sign-in, creates the session and redirects to `next`. |
| `/auth/me` | `GET` | Returns `{ "user": …, "expiresAt": … }`, or `401` with `SES_001` when signed out. |
| `/auth/logout` | `POST` | Ends the session, then redirects (`303`) to the provider's logout URL, or answers `{ "logoutUrl": … }` when the request sends `Accept: application/json`. |
| `/auth/logout/callback` | `GET` | The post-logout landing route: clears the sealed logout cookie and `303`s to the requested `next` path. Register its absolute URL as the application's `post_logout_redirect_uri`. |
| `/auth/backchannel-logout` | `POST` | Called by auth-service to end sessions. |

Mount the router at the root of your application: the path the handlers see must include the base path.

Open `https://app.example.com/auth/login?next=/api/profile` in a browser: you are sent to auth-service, sign in, and land on `/api/profile` with a session cookie. The cookie is `HttpOnly`, `Secure`, `SameSite=Lax` and prefixed with `__Host-` on HTTPS; the browser never sees a token. A signed-out request to `/api/profile` gets `401` and `{"error": {"code": "SES_001", "message": "Not signed in"}}`.

::callout{icon="i-lucide-info" color="info"}
Local development works over plain HTTP on loopback: `redirect_uri` may be `http://localhost:3000/auth/callback` (and only for `localhost`, `127.0.0.1` or `::1`). The cookies then lose the `Secure` flag and the `__Host-` prefix.
::
