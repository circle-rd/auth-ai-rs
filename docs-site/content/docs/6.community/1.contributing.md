Contributions are welcome. Read [CONTRIBUTING.md](https://github.com/circle-rd/auth-ai-rs/blob/main/CONTRIBUTING.md) for the process (versioning, releases, Git workflow) and [AGENTS.md](https://github.com/circle-rd/auth-ai-rs/blob/main/AGENTS.md) for the technical standards (typing, architecture, error handling, testing, security): both are mandatory for any contribution.

## Development workflow

Requires [rustup](https://rustup.rs) (the repository's `rust-toolchain.toml` pins Rust 1.89.0, the minimum supported version, with `clippy` and `rustfmt`) and a C toolchain (`cc`) for `aws-lc-sys`.

```sh
git clone https://github.com/circle-rd/auth-ai-rs.git
cd auth-ai-rs
cargo test --all-features
```

The tests run against a scripted mock identity provider plugged in through the `Transport` trait (`tests/support/mod.rs`): no auth-service instance, no network and no Docker are needed.

## Quality gates

A pull request must pass all of them, on the pinned Rust 1.89.0 and on stable:

| Command | What it checks |
| --- | --- |
| `cargo fmt --all --check` | Formatting. Run `cargo fmt --all` to fix it. |
| `cargo clippy --all-targets --all-features --locked -- -D warnings` | Lint, with every warning denied. |
| `cargo test --all-targets --all-features --locked` | The unit and integration suites. |
| `cargo test --doc --all-features --locked` | The doctests, including every README snippet. |
| `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features --locked` | The documentation builds without warnings. |
| `cargo audit` | Advisories of the dependencies that ship. |
| `cargo package --locked` | The crate that is published. |

## Rules in short

- **No `unsafe`.** `unsafe_code` is forbidden at crate level and must not be weakened.
- **No panics in production code.** Clippy denies `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!`, `dbg!`, printing and indexing that can panic. Tests may use them. Do not add `#[allow(...)]` to production code without a stated reason next to it.
- **Typed boundaries.** External data is deserialised into typed `serde` models before use; invalid configuration returns `CFG_001` at construction. Make invalid states unrepresentable with enums and validated builders.
- **One error type.** Every failure is an `AuthAiError` carrying an `ErrorCode`. A new code takes the next number of its domain prefix, a generic default message, an HTTP status in `web::status_for`, a test, and the same code in the TypeScript and Python SDKs. Anything that reaches a browser goes through `to_public_json()`.
- **Secrets.** Credentials are `SecretString`s (or the cookie `SealKey`) and never appear in `Debug` output, logs, errors or test output.
- **Async discipline.** Never block a Tokio worker, never hold a `std::sync::Mutex` across `.await`, put a timeout on every network call, and await every task you spawn.
- **Small modules.** Target at most 500 lines per file; 1000 is a hard limit.
- **Public API.** Everything exported from `auth_ai`, `auth_ai::server`, `auth_ai::web` and `auth_ai::axum` is public API: changing it is a breaking change, with a migration note in the changelog and no compatibility shim.

## Tests

Test behaviour (returned values, HTTP status, headers, observable side effects), not implementation details. Unit tests live beside the code; behaviour that spans modules is covered by the integration suites in `tests/`. Add to the mock identity provider rather than writing ad-hoc transports, and give every security check a test that fails when the check is removed.

## Documentation

This site lives in `docs-site/` (Nuxt 4 and Docus). Build it in Docker, without installing anything on your machine:

```sh
docker build -t auth-ai-rs-docs ./docs-site
docker run --rm -p 3000:3000 auth-ai-rs-docs
```

Then open `http://localhost:3000/auth-ai/rust/`. Every statement in the documentation must be traceable to the source in `src/`: update the pages, the rustdoc, the README quick start and the changelog in the same pull request as the code. The workflow `.github/workflows/docs.yml` builds and pushes the image on every push to `main`.

## Shared contract with the other SDKs

The wire contract (the BFF routes, the cookie formats and the error codes) is shared with the TypeScript SDK `@circle-rd/auth-ai` and the Python SDK `auth-ai`: change it in all of them, or not at all.

## Reporting a vulnerability

Do not open a public issue: use the [private advisory form](https://github.com/circle-rd/auth-ai-rs/security/advisories/new) described in [SECURITY.md](https://github.com/circle-rd/auth-ai-rs/blob/main/SECURITY.md).
