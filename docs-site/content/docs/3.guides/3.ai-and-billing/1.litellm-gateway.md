title: Call the LiteLLM gateway
description: Call LLMs and MCP tools through the gateway with the user's own token, handle empty wallets and rate limits, and attribute spend to a session.
---

Read [Credit wallet and LiteLLM gateway](/docs/concepts/wallet-and-gateway) first for the model. In short: the user's access token for the gateway audience is the API key, the **gateway debits the wallet**, and your application never handles a debit.

## Prerequisites

- **LiteLLM support** is on for the application in auth-service, and the plan of the user grants access to models (see the auth-service guide [LiteLLM gateway and credit wallet in an application](https://docs.circle-cyber.com/auth-service/docs/guides/integration/litellm-app)).
- `gateway_url` is set on the `AuthClientConfig` builder, and an `AiClient` exists: `AiClient::new(auth, grants)`.
- The user signed in **after** `gateway_url` was set, so their grant covers the gateway and wallet audiences.

## With the SDK's own calls

`UserAi::gateway()?.post_json(path, &body)` posts JSON and returns the parsed answer as a `serde_json::Value`; you validate it with a `serde` model. A refusal returns an `AuthAiError`.

```rust
use auth_ai::axum::{AuthError, AuthSession};
use auth_ai::web::{AuthHandlers, Session};
use auth_ai::{AiClient, AuthAiError, DetailValue, ErrorCode, UserAi, is_insufficient_credit};
use axum::extract::{FromRef, State};
use axum::http::{HeaderValue, StatusCode, header};
use axum::response::{IntoResponse, Response};
use axum::routing::post;
use axum::{Json, Router};
use serde::Deserialize;
use serde_json::json;

#[derive(Clone)]
struct AppState {
    handlers: AuthHandlers,
    ai: AiClient,
}

impl FromRef<AppState> for AuthHandlers {
    fn from_ref(state: &AppState) -> Self {
        state.handlers.clone()
    }
}

#[derive(Deserialize)]
struct ChatBody {
    model: String,
    message: String,
}

#[derive(Deserialize)]
struct ChatAnswer {
    choices: Vec<Choice>,
}

#[derive(Deserialize)]
struct Choice {
    message: ChoiceMessage,
}

#[derive(Deserialize)]
struct ChoiceMessage {
    content: Option<String>,
}

async fn ask(user: &UserAi, session: &Session, body: &ChatBody) -> Result<String, AuthAiError> {
    let answer = user
        .gateway()?
        .post_json(
            "/v1/chat/completions",
            &json!({
                "model": body.model,
                "messages": [{ "role": "user", "content": body.message }],
                "metadata": { "session_id": session.id },
            }),
        )
        .await?;
    let answer: ChatAnswer =
        serde_json::from_value(answer).map_err(|err| ErrorCode::Gw005.error().with_source(err))?;
    let first = answer.choices.into_iter().next();
    Ok(first
        .and_then(|choice| choice.message.content)
        .unwrap_or_default())
}

async fn chat(
    State(state): State<AppState>,
    AuthSession(session): AuthSession,
    Json(body): Json<ChatBody>,
) -> Result<Response, AuthError> {
    if body.model.is_empty() || body.message.is_empty() || body.message.len() > 2000 {
        return Err(ErrorCode::Req001.error().into());
    }
    let user = state.ai.for_user(&session.user_id)?;
    let response = match ask(&user, &session, &body).await {
        Ok(reply) => Json(json!({ "reply": reply })).into_response(),
        Err(err) if is_insufficient_credit(&err) => {
            let body =
                json!({ "error": err.to_public_json(), "topupUrl": user.wallet.topup_url() });
            (StatusCode::PAYMENT_REQUIRED, Json(body)).into_response()
        }
        Err(err) if err.code() == ErrorCode::Gw002 => {
            let mut response = (
                StatusCode::TOO_MANY_REQUESTS,
                Json(json!({ "error": err.to_public_json() })),
            )
                .into_response();
            if let Some(DetailValue::Float(seconds)) = err.detail("retryAfterSeconds") {
                response.headers_mut().insert(
                    header::RETRY_AFTER,
                    HeaderValue::from(seconds.round() as u64),
                );
            }
            response
        }
        Err(err) => (
            StatusCode::BAD_GATEWAY,
            Json(json!({ "error": err.to_public_json() })),
        )
            .into_response(),
    };
    Ok(response)
}

fn chat_routes() -> Router<AppState> {
    Router::new().route("/api/chat", post(chat))
}
```

The gateway maps to the SDK's errors by status: `402` is `GW_001` (empty wallet), `429` is `GW_002` (rate limit, with the `retryAfterSeconds` detail when the gateway sends `Retry-After`), `401` and `403` are `GW_003`, `503` is `GW_004`. Return the **public** JSON to your users and keep `err.message()` for logs.

You do not have to catch these errors yourself: an `AuthError` returned from a route is answered with the public envelope and the status of its code (`402` for `GW_001`, `429` for `GW_002`…). Catch them when you want to add something, such as the `topupUrl` above.

## With an OpenAI-compatible client

A client that signs its own requests (an OpenAI-compatible library, a streaming call, an MCP client) takes two things from the SDK: `gateway.openai_base_url()` (`<gateway_url>/v1`) and a token from `gateway.access_token().await?`, a `SecretString` to read with `expose_secret()`. **Fetch the token for every request**: it lives one hour, is cached by the grant manager and never stored. Point such a client only at the gateway: unlike `post_json`, it does not lock the token to the gateway's origin.

```rust
use auth_ai::{UserAi, is_insufficient_credit_status};
use serde_json::{Value, json};

async fn say_hello(
    user: &UserAi,
    session_id: &str,
) -> Result<Option<String>, Box<dyn std::error::Error>> {
    let gateway = user.gateway()?;
    // Fetched for every request: the token lives one hour and is never stored.
    let token = gateway.access_token().await?;
    let response = reqwest::Client::new()
        .post(format!("{}/chat/completions", gateway.openai_base_url()))
        .bearer_auth(token.expose_secret())
        .json(&json!({
            "model": "gpt-4o-mini",
            "messages": [{ "role": "user", "content": "Hello" }],
            "metadata": { "session_id": session_id },
        }))
        .send()
        .await?;
    let status = response.status().as_u16();
    if is_insufficient_credit_status(status) {
        return Ok(None); // 402: the wallet is empty or negative. Offer a top-up.
    }
    if status == 401 {
        gateway.invalidate_token(); // the next call mints a new token
    }
    let completion: Value = response.error_for_status()?.json().await?;
    Ok(completion["choices"][0]["message"]["content"]
        .as_str()
        .map(str::to_owned))
}
```

::callout{icon="i-lucide-info" color="info"}
This snippet only relies on the documented SDK API and on `reqwest` (with its `json` feature); it was compile-checked. Model names depend on your gateway: list them with `gateway.list_models()`. For a client library, set its base URL to `openai_base_url()` and its API key to the token, built per request.
::

A `401` from the gateway means it refused the token: call `gateway.invalidate_token()` after a request you signed yourself, so the next `access_token()` mints a new one. (`post_json` does it for you.) Tokens live one hour and are never stored.

`is_insufficient_credit_status(status)` tests an HTTP status for `402`, which is how a client library or a raw response exposes it. For `AuthAiError`s use `is_insufficient_credit(&err)`. To turn a failed raw response into the SDK's own error, `to_gateway_error(status, body, headers)` applies the mapping above.

## Attribute spend to a session

Put `"metadata": { "session_id": "<id>" }` in the request body. The wallet then keeps the spend of that session, and you can read it back (for the calling application only):

```rust
use auth_ai::{AuthAiError, UserAi, format_euros};

async fn print_usage(user: &UserAi) -> Result<(), AuthAiError> {
    let usage = user.wallet.get_session_usage("chat-7f3a", Some(7)).await?;
    println!(
        "{} calls, {} EUR",
        usage.calls,
        format_euros(usage.total, 2)?
    );
    for entry in &usage.by_model {
        println!("{} {} {}", entry.model, entry.count, entry.total_tokens);
    }
    Ok(())
}
```

`usage.total` is an `i128` (`Amount`) of micro-euros; `by_model` lists `model`, `amount`, `count` and token counts per model (`model` is `mcp` for tool calls and `other` when the gateway reported none). Billing is asynchronous: a call may take a few seconds to appear, so poll if you need the figure right after the call.

## Models, agents and MCP servers

```rust
use auth_ai::{AuthAiError, GatewayClient};

async fn discover(gateway: &GatewayClient) -> Result<String, AuthAiError> {
    let models = gateway.list_models().await?; // /v1/models, only what the user may call
    let agents = gateway.list_agents().await?; // /v1/agents
    let servers = gateway.list_mcp_servers().await?; // /v1/mcp/server
    println!("{} {} {}", models.len(), agents.len(), servers.len());

    let url = gateway.mcp_url(None)?; // <gateway_url>/mcp
    let one_server = gateway.mcp_url(Some("my-server"))?; // <gateway_url>/my-server/mcp
    println!("{url} {one_server}");
    // For an MCP client's Authorization: Bearer header.
    Ok(gateway.access_token().await?.expose_secret().to_owned())
}
```

`mcp_url(Some(name))` rejects names outside `[A-Za-z0-9][A-Za-z0-9_.-]{0,127}`, and the reserved name `v1`, with `CFG_001`. Mint the token per connection: it expires after an hour.

## Show the balance first

Check `user.wallet.get_account().await?` before an expensive action and use `can_spend`, never the raw balance: it is true for an unlimited account or a strictly positive balance. A call that finishes after the balance reached zero is still billed, so a balance can go negative until the next top-up.
