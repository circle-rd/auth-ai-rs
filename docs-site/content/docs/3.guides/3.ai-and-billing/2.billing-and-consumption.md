title: Billing and consumption
description: From your backend, read a user's subscription, metered usage and invoices, and report consumption with idempotency keys.

The machine API calls auth-service **as your application**, with a `client_credentials` token minted from the application's own secret. It never acts as a user, and it can only read and write the data of your application. Concepts and endpoints are documented in auth-service: [Consumption tracking](https://docs.circle-cyber.com/auth-service/docs/guides/administration/consumption-tracking) and [Stripe integration](https://docs.circle-cyber.com/auth-service/docs/guides/administration/stripe-integration).

## Prerequisites

- A **confidential** application: `MachineApi::new(&auth)` returns `CFG_001` without a client secret.
- The machine scopes `billing:read`, `consumption:read` and `consumption:write`. New confidential applications receive them by default (with `resources:validate`); an application created before that needs a superadmin to set them. A missing scope makes the call return `TOK_004` with the scope in the `scope` detail.

```rust
use auth_ai::server::MachineApi;
use auth_ai::{AuthAiError, AuthClient, AuthClientConfig};

fn machine_api() -> Result<MachineApi, AuthAiError> {
    let auth = AuthClient::new(
        AuthClientConfig::builder(
            "https://auth.example.com",
            "my-app",
            "https://app.example.com/auth/callback",
        )
        .client_secret("<client-secret>")
        .build()?,
    )?;
    MachineApi::new(&auth)
}
```

`MachineApi` is `Clone`, and it has three members: `billing`, `consumption` and `resources`. Tokens are cached per scope until shortly before they expire, and simultaneous callers share one request to the token endpoint.

## Read a user's billing

```rust
use auth_ai::AuthAiError;
use auth_ai::server::MachineApi;

async fn show_billing(machine: &MachineApi, user_id: &str) -> Result<(), AuthAiError> {
    if let Some(subscription) = machine.billing.get_subscription(user_id).await?
        && subscription.is_active
    {
        println!(
            "{} {:?}",
            subscription.plan.name, subscription.current_period_end
        );
    }

    let usage = machine.billing.get_usage(user_id).await?;
    for feature in &usage.features {
        // usage_limit -1 is unlimited; remaining is None when unlimited
        println!(
            "{} {} {:?}",
            feature.feature_key, feature.used, feature.remaining
        );
    }
    Ok(())
}
```

`get_subscription` returns `None` when the user holds no subscription. The `user_id` is the user's `sub`.

Invoices are keyset-paginated, newest first (`limit` is 1 to 100):

```rust
use auth_ai::AuthAiError;
use auth_ai::server::{InvoiceView, MachineApi};

async fn all_invoices(
    machine: &MachineApi,
    user_id: &str,
) -> Result<Vec<InvoiceView>, AuthAiError> {
    let mut invoices = Vec::new();
    let mut cursor: Option<String> = None;
    loop {
        let page = machine
            .billing
            .list_invoices(user_id, Some(50), cursor.as_deref())
            .await?;
        invoices.extend(page.items);
        match page.next_cursor {
            Some(next) => cursor = Some(next),
            None => return Ok(invoices),
        }
    }
}
```

Amounts of an invoice (`amount_due`, `amount_paid`, `amount_remaining`) are integers in cents.

## Report consumption

```rust
use auth_ai::AuthAiError;
use auth_ai::server::MachineApi;

async fn record_export(machine: &MachineApi, user_id: &str) -> Result<(), AuthAiError> {
    let result = machine
        .consumption
        .report(user_id, "exports", 1_i64, Some("export-job-8c1f"))
        .await?;
    println!("{} {}", result.aggregate.total, result.metered);
    Ok(())
}
```

- `key` is 1 to 64 characters from `a-zA-Z0-9.`; `value` is anything that converts into a `ConsumptionValue`: an `i64`, `i32`, `u32` or a finite `f64` (negative credits back). The SDK validates both, and the user id and the idempotency key, before sending and returns `CFG_001` otherwise.
- `aggregate.total` is a **decimal string**: a running total is not bounded by a double.
- **Set the idempotency key** (the last argument) to a stable identifier of the business event (a job id, an order line; at most 200 characters once trimmed). The same key reported twice counts once, which makes retries safe; with `None`, every call counts.

### Counters and metered features

| | Plain counter | Metered feature |
| --- | --- | --- |
| When | The `key` is any other key. | The `key` is the `featureKey` of a metered price on the plan of the user's active subscription. |
| `metered` in the result | `false` | `true` |
| Rules | Any finite `value`. | `value` must be greater than zero; a report that would pass the plan's cap is refused. |
| Read back with | `machine.consumption.list_aggregates(user_id)` or `.get_aggregate(user_id, key)` | `machine.billing.get_usage(user_id)` |

When the plan's cap is exceeded, auth-service answers with its own error, which the SDK returns as `API_001`: look at the `apiCode` detail (`BIL_003` for the cap, `BIL_002` for a non-positive value) and the `status` detail.

```rust
use auth_ai::server::MachineApi;
use auth_ai::{AuthAiError, DetailValue};

enum Outcome {
    Ok,
    Quota,
}

async fn record_job(
    machine: &MachineApi,
    user_id: &str,
    job_id: &str,
) -> Result<Outcome, AuthAiError> {
    let key = format!("export-{job_id}");
    match machine
        .consumption
        .report(user_id, "exports", 1_i64, Some(&key))
        .await
    {
        Ok(_) => Ok(Outcome::Ok),
        Err(err) if err.detail("apiCode").and_then(DetailValue::as_str) == Some("BIL_003") => {
            Ok(Outcome::Quota)
        }
        Err(err) => Err(err),
    }
}
```

Reading a key that was never reported fails: `get_aggregate` returns `API_001` with the `apiCode` detail set to `CONS_003`.

## Where to call it

Always from your **backend**: it needs the application secret. A typical flow is a signed-in request handler that knows `session.user_id`, performs the work, then reports consumption. Keep the pre-check (`get_usage`, `remaining`) as a courtesy to the user and rely on the report's refusal as the authoritative cap.
