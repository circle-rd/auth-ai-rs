Use this guide when **your service is the resource**: a REST API, or an MCP server, that receives auth-service access tokens from other clients. (To sign users in to a web app, see [axum backend](/docs/guides/backend/axum).)

## How it works

1. Your API has a URL that serves as its **audience** (RFC 8707 resource identifier), for example `https://api.example.com`. auth-service lets an application request tokens for it.
2. A client obtains an access token whose `aud` contains that URL.
3. Your API verifies the JWT with `BearerVerifier`: signature, issuer, audience, expiry and a client binding. It then checks scopes and entitlements.
4. Unauthenticated clients learn where to sign in from the `WWW-Authenticate` header and the RFC 9728 metadata document, which is how MCP clients discover the authorization server.

Opaque tokens are refused: they carry no audience your API could trust.

## A complete axum route

```rust [src/main.rs]
use auth_ai::axum::AuthError;
use auth_ai::server::{
    BearerError, BearerVerifier, bearer_challenge, protected_resource_metadata,
    protected_resource_metadata_path, require_scopes,
};
use auth_ai::{AuthAiError, AuthClient, AuthClientConfig, ErrorCode, has_role};
use axum::extract::State;
use axum::http::{HeaderMap, StatusCode, header};
use axum::response::{IntoResponse, Response};
use axum::routing::get;
use axum::{Json, Router};
use serde_json::{Value, json};

const RESOURCE: &str = "https://api.example.com";

#[derive(Clone)]
struct ApiState {
    auth: AuthClient,
    verifier: BearerVerifier,
    metadata_url: String,
}

// RFC 9728: served without authentication.
async fn metadata(State(state): State<ApiState>) -> Json<Value> {
    Json(protected_resource_metadata(
        &state.auth,
        RESOURCE,
        Some(&["openid", "profile", "email", "roles", "features"]),
    ))
}

async fn reports(State(state): State<ApiState>, headers: HeaderMap) -> Result<Response, AuthError> {
    let authorization = headers
        .get(header::AUTHORIZATION)
        .and_then(|value| value.to_str().ok());
    let verified = state.verifier.verify_header(authorization).await;
    let token = match verified.and_then(|token| require_scopes(&token, &["roles"]).map(|()| token))
    {
        Ok(token) => token,
        Err(err) => return challenge(&state, err),
    };
    if token.user_id.is_some() && !has_role(&token.claims, "analyst") {
        let denied = Json(json!({ "error": { "code": "FORBIDDEN" } }));
        return Ok((StatusCode::FORBIDDEN, denied).into_response());
    }
    let caller = token.user_id.as_deref().unwrap_or(&token.client_id);
    Ok(Json(json!({ "caller": caller })).into_response())
}

fn challenge(state: &ApiState, err: AuthAiError) -> Result<Response, AuthError> {
    let (status, error) = match err.code() {
        // No credentials were presented.
        ErrorCode::Tok003 => (StatusCode::UNAUTHORIZED, None),
        ErrorCode::Tok001 => (StatusCode::UNAUTHORIZED, Some(BearerError::InvalidToken)),
        ErrorCode::Tok004 => (StatusCode::FORBIDDEN, Some(BearerError::InsufficientScope)),
        // Not the caller's fault (the provider cannot be discovered, for example).
        _ => return Err(AuthError(err)),
    };
    let www_authenticate = bearer_challenge(&state.metadata_url, error, None)?;
    let body = Json(json!({ "error": err.to_public_json() }));
    Ok((status, [(header::WWW_AUTHENTICATE, www_authenticate)], body).into_response())
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // A pure resource server never signs users in, but the configuration still
    // requires a client id and a redirect URI.
    let auth = AuthClient::new(
        AuthClientConfig::builder(
            "https://auth.example.com",
            "my-api",
            "https://api.example.com/auth/callback",
        )
        .build()?,
    )?;
    let verifier = BearerVerifier::new(auth.clone(), RESOURCE)?;

    let metadata_path = protected_resource_metadata_path(RESOURCE)?;
    let state = ApiState {
        auth,
        verifier,
        metadata_url: format!("{RESOURCE}{metadata_path}"),
    };
    let app = Router::new()
        .route(&metadata_path, get(metadata))
        .route("/v1/reports", get(reports))
        .with_state(state);
    axum::serve(tokio::net::TcpListener::bind("0.0.0.0:3000").await?, app).await?;
    Ok(())
}
```

`BearerVerifier::new` fails with `CFG_001` when the audience is not an absolute URL, and `protected_resource_metadata_path` when the resource is not. `AuthError` is the `axum` feature's way to answer an `AuthAiError` with the public envelope; the route above only needs it for the failures that are not a bearer problem. Without the `axum` feature, `auth_ai::web::error_response(&err, None, Vec::new())` builds the same envelope as a `WebResponse`.

## What you get back

`verify` and `verify_header` return a `VerifiedAccessToken`:

| Field | For a user token | For a `client_credentials` token |
| --- | --- | --- |
| `user_id` | `Some(sub)`: the user. | `None` |
| `client_id` | The application the user signed in with (`azp`). | The calling application. |
| `scopes` | A `Vec<String>` of the granted scopes. | The granted machine scopes. |
| `audiences` | A `Vec<String>` of the token's `aud` values. | Same. |
| `claims` | An `AccessTokenClaims`, which includes `roles`, `permissions`, `features`, `plan`, `org_id` when their scopes were granted. | No user claims. |

Distinguish the two with `user_id.is_none()`: a machine caller must not be treated as a user.

## Which error becomes which answer

| `ErrorCode` | Meaning | Answer |
| --- | --- | --- |
| `Tok003` | No `Authorization: Bearer` header, or a malformed one. | `401`, challenge without `error` (the client has not presented credentials). |
| `Tok001` | Bad signature, wrong audience or issuer, expired, opaque token, token not bound to a client. | `401`, challenge with `error="invalid_token"`. |
| `Tok004` | A required scope is missing (the `missing` detail names it). | `403`, challenge with `error="insufficient_scope"`. |

`require_scopes(&token, &["roles"])` fails with `TOK_004` when any listed scope is absent. `bearer_challenge` fails with `CFG_001` when a value contains `"`, `\`, CR or LF, so a header can never be injected through it. Other codes, such as `OIDC_001` when the provider cannot be discovered, are not the caller's fault: let them propagate as a server error, as the example does.

## Getting a token for your API

- **A signed-in user of your web app** calls your API with a token minted from their grant: add the API URL to `resources` in the `AuthClientConfig` builder, then `grants.get_access_token(sub, Some(resource)).await?`.
- **Another service** uses the `client_credentials` grant with `auth.client_credentials(scope, Some(resource)).await?`; its own application must be allowed to request your URL. It needs a client secret.
- **An MCP client** finds the authorization server from your metadata document and runs its own authorization-code flow. The auth-service guide [MCP integration](https://docs.circle-cyber.com/auth-service/docs/guides/integration/mcp-integration) covers the provider side.

In every case auth-service rejects a resource it does not know, or that the application is not linked to, with `invalid_target`.

::callout{icon="i-lucide-info" color="info"}
Verification fetches the provider's signing keys once and caches them (for an hour at most); an unknown key id triggers at most one reload per second, so key rotation is picked up without a restart and a flood of forged tokens cannot hammer the provider.
::

## Receive back-channel logout

When your API keeps its own sessions, auth-service tells it when a provider session ends. `BackchannelLogoutHandler` verifies the logout token (signature, `typ`, audience, event, lifetime, replay) and calls your callback with the `sid` and the `sub`:

```rust
use std::sync::Arc;

use auth_ai::axum::{AuthError, into_response, to_web_request};
use auth_ai::server::{BackchannelLogoutHandler, LogoutCallback, ReplayStore};
use auth_ai::{AuthClient, ErrorCallback};
use axum::Router;
use axum::body::Body;
use axum::extract::{Request, State};
use axum::response::{IntoResponse, Response};
use axum::routing::post;

const ORIGIN: &str = "https://api.example.com";

// Called without cookies: no session or CSRF layer in front of it.
async fn backchannel_logout(
    State(handler): State<Arc<BackchannelLogoutHandler>>,
    request: Request<Body>,
) -> Response {
    match to_web_request(request, ORIGIN, true).await {
        Ok(web) => into_response(handler.handle(&web).await),
        Err(err) => AuthError(err).into_response(),
    }
}

fn logout_routes(auth: AuthClient, replay_store: Arc<dyn ReplayStore>) -> Router {
    let on_logout: LogoutCallback = Arc::new(|event| {
        Box::pin(async move {
            // End your own sessions whose provider session is `event.sid`.
            tracing::info!(sid = %event.sid, sub = %event.sub, "provider session ended");
            Ok(())
        })
    });
    let on_error: ErrorCallback = Arc::new(|err| {
        tracing::warn!(error = %err.to_json(), "logout token refused");
    });
    let handler = BackchannelLogoutHandler::new(auth, on_logout)
        .replay_store(replay_store)
        .on_error(on_error);
    Router::new()
        .route("/auth/backchannel-logout", post(backchannel_logout))
        .with_state(Arc::new(handler))
}
```

- The endpoint answers `200` for an accepted token, `400` `{"error": "invalid_request"}` for any refused one (the cause goes to `on_error`, never to the response) and `500` when your callback fails.
- Register its absolute URL as the application's back-channel logout URI. It must be reachable by auth-service over HTTPS.
- Share the `ReplayStore` across replicas (see [Implement the stores](/docs/guides/backend/custom-stores)): the default one is in memory.
- With `AuthHandlers`, this endpoint is already served at `<base_path>/backchannel-logout` and ends the sessions of the sign-in handlers for you; use `BackchannelLogoutHandler` only for sessions of your own.
