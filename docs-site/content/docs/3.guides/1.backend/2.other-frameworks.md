description: Mount the framework-agnostic sign-in handlers in Actix Web or any other Rust web framework, with a small bridge between WebRequest, WebResponse and your framework.

`AuthHandlers` works on two small framework-agnostic types: `handlers.handle(&request).await` takes a `WebRequest` and resolves to `Some(WebResponse)`, or to `None` when the path is not one of its routes. axum gets a ready-made adapter ([axum backend](/docs/guides/backend/axum)); for anything else you write a thin bridge. There is no Actix Web, Rocket or Warp adapter in version 0.x.

::callout{icon="i-lucide-info" color="info"}
The snippet below only relies on the documented SDK API. It was compile-checked against Actix Web 4, but it is not part of the SDK's own test suite. The adapter in `auth_ai::axum` is the same bridge for axum: read `src/axum.rs` in the repository as a second example.
::

## The types

| Type | Members |
| --- | --- |
| `WebRequest` | `method` (`String`, upper case), `url` (`String`, absolute: the SDK reads only its path and query), `headers` (`Vec<(String, String)>`, names in lower case) and `body` (`Vec<u8>`). `WebRequest::new(method, url)` upper-cases the method; `with_header(name, value)` and `with_body(body)` extend it; `request.header(name)` returns the first value of a header, case-insensitively. |
| `WebResponse` | `status` (`u16`), `headers` (`Vec<(String, String)>`, so that `Set-Cookie` can appear several times) and `body` (`Vec<u8>`). `header(name)`, `header_values(name)` and `json()` read it back. |

Both are exported from `auth_ai`. `json_response` and `redirect_response` build a `WebResponse` for your own routes; they set `Cache-Control: no-store`.

## The contract your bridge must honour

1. Call `handlers.handle(&request)` for every request below `handlers.base_path()`. When it returns `None`, answer `404` or continue with your own routing.
2. Build the `WebRequest` URL from the registered origin, `handlers.origin()`, followed by the path and query of the incoming request. The SDK does not read the `Host` header, and your bridge should not either.
3. Send **every** header pair of the response: `Set-Cookie` appears more than once on a sign-in, so never collapse the headers into a map.
4. Give `POST /auth/backchannel-logout` its form body as bytes (`application/x-www-form-urlencoded`, at most `auth_ai::server::MAX_BODY_BYTES`, 16 KiB: a larger body is refused with `400`). Configure your framework's payload limit to that value so the body is not buffered first, and mount the route outside any CSRF or session middleware: auth-service calls it with no cookies.
5. Protect your own routes with `handlers.get_session(&request)` or `handlers.require_session(&request)`, and answer failures with the public error envelope: `auth_ai::web::error_response(&err, handlers.on_error(), Vec::new())` builds the `WebResponse` with the status the SDK uses for each code.

## An Actix Web bridge

Two conversion functions, one catch-all route below `base_path`, and one protected route of your own:

```rust [src/main.rs]
use std::sync::Arc;

use actix_web::http::StatusCode;
use actix_web::{App, HttpRequest, HttpResponse, HttpServer, web};
use auth_ai::server::MAX_BODY_BYTES;
use auth_ai::web::{AuthHandlers, MemorySessionStore, SessionStore, error_response};
use auth_ai::{
    AuthClient, AuthClientConfig, GrantManager, MemoryGrantStore, WebRequest, WebResponse,
};

fn to_web_request(handlers: &AuthHandlers, request: &HttpRequest, body: &[u8]) -> WebRequest {
    // Built on the registered origin: the Host header is never trusted.
    let query = request.query_string();
    let url = if query.is_empty() {
        format!("{}{}", handlers.origin(), request.path())
    } else {
        format!("{}{}?{query}", handlers.origin(), request.path())
    };
    let mut web = WebRequest::new(request.method().as_str(), url).with_body(body);
    for (name, value) in request.headers() {
        web = web.with_header(name.as_str(), String::from_utf8_lossy(value.as_bytes()));
    }
    web
}

fn to_http_response(response: WebResponse) -> HttpResponse {
    let status = StatusCode::from_u16(response.status).unwrap_or(StatusCode::INTERNAL_SERVER_ERROR);
    let mut builder = HttpResponse::build(status);
    // One pair per header line: repeated Set-Cookie headers stay apart.
    for (name, value) in response.headers {
        builder.append_header((name, value));
    }
    builder.body(response.body)
}

async fn auth_routes(
    handlers: web::Data<AuthHandlers>,
    request: HttpRequest,
    body: web::Bytes,
) -> HttpResponse {
    let web = to_web_request(&handlers, &request, &body);
    match handlers.handle(&web).await {
        Some(response) => to_http_response(response),
        None => HttpResponse::NotFound().finish(),
    }
}

async fn profile(handlers: web::Data<AuthHandlers>, request: HttpRequest) -> HttpResponse {
    let web = to_web_request(&handlers, &request, &[]);
    match handlers.require_session(&web).await {
        Ok(session) => HttpResponse::Ok().json(serde_json::json!({ "sub": session.user_id })),
        // The public envelope, with the status the SDK itself uses for this code.
        Err(err) => to_http_response(error_response(&err, handlers.on_error(), Vec::new())),
    }
}

#[actix_web::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = AuthClientConfig::builder(
        std::env::var("AUTH_ISSUER")?,
        "my-app",
        "https://app.example.com/auth/callback",
    )
    .client_secret(std::env::var("AUTH_CLIENT_SECRET")?)
    .build()?;
    let auth = AuthClient::new(config)?;
    let sessions: Arc<dyn SessionStore> = Arc::new(MemorySessionStore::new());
    let handlers = AuthHandlers::builder(
        auth.clone(),
        GrantManager::new(auth, MemoryGrantStore::new()),
        sessions,
        std::env::var("AUTH_COOKIE_SECRET")?,
    )
    .build()?;
    let base_path = handlers.base_path().to_owned();
    let handlers = web::Data::new(handlers);

    HttpServer::new(move || {
        App::new()
            .app_data(handlers.clone())
            .app_data(web::PayloadConfig::new(MAX_BODY_BYTES))
            .route(&format!("{base_path}/{{tail:.*}}"), web::to(auth_routes))
            .route("/api/profile", web::get().to(profile))
    })
    .bind(("0.0.0.0", 3000))?
    .run()
    .await?;
    Ok(())
}
```

`AuthHandlers` is cheap to clone and its clones share their state, so one value is enough for every worker. If you add CSRF protection to your application, keep it off the `base_path` routes (the back-channel route is called without cookies) and on your own state-changing routes.

## Other frameworks

The two conversion functions are all a bridge needs: build a `WebRequest` from the framework's request, and turn a `WebResponse` back. Only the header and body types change. In a framework built on the `http` crate (hyper, Warp, a Tower service), the headers come from `HeaderMap` and the response from `http::Response::builder()`, with each header pair appended rather than inserted.

## Blocking frameworks

The SDK is async only: its futures run on a Tokio runtime, and it spawns the tasks that must not be interrupted half-way (a refresh-token rotation, a revocation) on it. There is no blocking facade. A synchronous framework has to own a runtime and drive the SDK from it, which this documentation does not cover.

## Stores on serverless platforms

The stores must be shared by every instance (see [Implement the stores](/docs/guides/backend/custom-stores)), which rules out the in-memory stores on serverless platforms.
