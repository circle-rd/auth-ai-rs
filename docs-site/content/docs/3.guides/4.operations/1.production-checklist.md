title: Production checklist
description: "What to change before the first real user signs in: stores, locks, secrets, URLs, logout, logging, dependencies and the toolchain."
---

The quick start uses in-memory stores so that it runs with no setup. Work through this list before deploying.

## Storage

- [ ] **`SessionStore` on your database.** `MemorySessionStore` loses every session on restart and cannot be shared. Index `user_id` and the provider session id, and purge expired rows. See [Implement the stores](/docs/guides/backend/custom-stores).
- [ ] **`GrantStore` on your database, encrypted at rest.** It holds one long-lived refresh token per user.
- [ ] **A distributed `GrantLock`** when you run several replicas (or several worker processes), so two of them never rotate the same grant at once. The default lock only covers one process.
- [ ] **A shared `ReplayStore`** when you run several replicas (for example Redis `SET NX PX`), so a logout token replayed on another instance is refused.

## Secrets

- [ ] **Cookie secret of at least 32 random characters** (`openssl rand -base64 48`), from your secret manager or environment. Shorter secrets are refused with `CFG_001`. Rotating it only invalidates sign-ins in progress: the session cookie is an opaque random id and is not sealed with it.
- [ ] **Client secret** from the environment. Without `client_secret` the SDK acts as a public client and the machine API is unavailable, so fail at startup on a missing variable rather than leaving the secret out.
- [ ] Nothing secret in source control, logs or error responses. Credentials are `SecretString`s: read them with `expose_secret()` at the point of use only.

## URLs and registration

- [ ] **`redirect_uri` is `<origin><base_path>/callback`**, over HTTPS, and registered identically in auth-service. The `AuthHandlers` builder refuses a mismatch.
- [ ] **`post_logout_redirect_uri`** is registered if you set it.
- [ ] **Back-channel logout URI** `<origin><base_path>/backchannel-logout` is registered in auth-service: HTTPS and reachable **from auth-service**. auth-service waits for these deliveries when a user signs out, so keep the endpoint fast.
- [ ] **End-session or the back-channel URI is enabled**, so the ID token carries `sid`. Keep `require_provider_session` at its default (`true`).
- [ ] **LiteLLM support** is on and `gateway_url` matches the gateway URL exactly (no trailing slash), when you use the gateway.
- [ ] **Machine scopes** `billing:read`, `consumption:read`, `consumption:write` are granted, when you use the machine API. `resources:authorize` is granted only to a trusted enforcement point, and `resources:usage:write` only to a platform metering component.
- [ ] Your reverse proxy forwards the `/auth/*` paths, the `Cookie`, `Origin` and `Sec-Fetch-Site` headers and the request body of the back-channel route unchanged, and terminates TLS (consider HSTS).

## Application behaviour

- [ ] **Entitlements are enforced on the server**, in each route, not only hidden in the UI.
- [ ] **Your own `POST`, `PUT`, `PATCH` and `DELETE` routes check `Origin`**, as the SDK does for `/auth/logout` (`auth_ai::web::is_cross_site` does the test).
- [ ] **The back-channel route stays outside session and CSRF protection**: it is called without cookies.
- [ ] **`on_sessions_ended`** closes sockets or drops caches of the users whose sessions ended.
- [ ] Tune **`session_ttl_seconds`** (8 hours by default) and **`claims_renew_seconds`** (15 minutes by default) to how quickly role and plan changes must reach users.
- [ ] **Shut down gracefully** (for example `axum::serve(...).with_graceful_shutdown(...)`) so that a refresh-token rotation in flight finishes before the process exits. `AuthClient` shares one HTTP client between its clones and has nothing to close.
- [ ] **Every call has a timeout.** The SDK applies `timeout` (10 seconds by default) to each request it makes, and the default transport bounds every response body. Set your own limits on the requests your server accepts.

## Logging and errors

- [ ] **`on_error` is set** and logs `err.to_json()` for `AuthAiError`s: it is the only place the real cause of a failed sign-in appears.
- [ ] **Query strings are not logged**: the callback URL carries the authorization code. `tower_http`'s `TraceLayer` records the full URI by default: see [Keep the authorization code out of the logs](/docs/guides/backend/axum#keep-the-authorization-code-out-of-the-logs).
- [ ] **Responses use `to_public_json()`** (or `AuthError` in axum), never `message()` or `details()`.

## Dependencies and toolchain

- [ ] **Rust 1.89 or later.** Pin the toolchain with a `rust-toolchain.toml`, commit `Cargo.lock` and build with `--locked`, so the build you tested is the build you ship. A C toolchain is needed to build `aws-lc-sys`.
- [ ] **Keep `axum` and `tokio` current** (and the rest of your web stack): they sit on your request path, so take the releases that carry security fixes. Run **`cargo audit`** in CI, and review advisories before upgrading.
- [ ] **Signing algorithms.** auth-service signs with ES256 (or RS256). The SDK verifies ES256/384/512, RS256/384/512, PS256/384/512 and the fully specified `Ed25519`, pinned to the single algorithm the provider advertises. `EdDSA` (deprecated by RFC 9864), HMAC and `none` are never accepted. `Ed448` is not supported: a provider that only advertises it fails discovery with `OIDC_001`.
- [ ] Server clocks are synchronised (token verification allows `clock_tolerance_seconds`, 5 by default).
- [ ] If you need a proxy, mutual TLS or request tracing towards auth-service and the gateway, implement the `Transport` trait and build the client with `AuthClient::with_transport`.

## Verify end to end

Sign in against your auth-service from a browser, then check each part you use: `GET /auth/me` after a claims renewal, a wallet read, a gateway call, a billing read and a consumption report, and a sign-out from another application to see the back-channel logout end the session. Make sure no log line contains a token, a secret or an authorization code.
